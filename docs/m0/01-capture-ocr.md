# M0-01 窗口截取 + Windows OCR 实测

> 日期：2026-09-15。验证代码：`spikes/capture-ocr`（windows-capture 2.0.1 + windows 0.62 的 `Windows.Media.Ocr`）。
> 环境：Windows 11 Pro 22631，RTX 3060。样本图由 `spikes/capture-ocr/fixtures/gen.ps1` 生成（合成图，不含真实聊天内容）。

## 结论速览

| 项 | 结果 | 对架构的影响 |
|---|---|---|
| OCR 语言包 | **已确认**本机装有 `en-US`、`zh-Hans-CN` | 首发不用引导用户装语言包，但仍需检测缺失并提示 |
| 按窗口截取 | **已确认**可用（记事本 1426×1361） | 走 Windows.Graphics.Capture 路线成立 |
| 截图会话启动 | 首帧 **594 ms**（包含建立会话） | 产品中必须**保持常驻会话**、持续接帧，不能每次识别都新建会话 |
| 最小化窗口 | **已确认不产出帧**（Chrome 最小化时 3 s 超时） | 读取管道要识别"目标已最小化"状态并在 UI 提示，不能静默卡住 |
| 去掉黄色边框 | `WithoutBorder` 设置未报错 | 是否真的没有边框，还需肉眼确认一次 |
| 被遮挡窗口 | 记事本当时很可能被 Claude 窗口遮挡，仍然截到了完整内容 | **未严格验证**，要专门做一次遮挡测试 |
| OCR 速度 | 小区域（420×110～1040×520）**16～42 ms**；整窗 1426×1361 为 277 ms | 只识别框选区域，速度完全够用，瓶颈会在翻译 |

## 识别准确率

### 网页气泡（Segoe UI 10.5pt，白底/蓝底）

| 原文 | 放大 1× | 放大 2× |

### 中文（记事本整窗，zh-Hans-CN）
正文基本全对，但**每个汉字之间都被插入空格**（`测 试 方 法`），数字间也有空格（`10 ． 8MM`）。

## 发现与修正

1. **最初假设"放大越多识别越准"，实测不是这样**：2× 修好了小写 i，却新引入了 `lol→101`；3× 修好了 `[Party]`，又把 `5?` 认成了 `50`。放大倍数不是单调变好的。→ 预处理参数必须**按预设可调**，并用样本回归测试来选，不能写死一个值。
2. **数字和符号出错最危险**：`$40 → 540` 会改变原意，翻译模型也纠正不了。→ 译文面板要能**一键看 OCR 原文**；带数字、金额的句子在 UI 上加标记，提醒用户核对原图。
3. **PrefixParser 必须容错**：括号被认成 `l`、`)`、`,'`。→ 行首解析要做模糊匹配（`[` 后接频道名，结尾可以是 `] ) l`），不能用严格的正则。
4. **中文 OCR 结果需要规范化**：删掉 CJK 字符之间的空格、把全角标点统一。这是 domain 层的纯函数，要配单测。
5. **合成图不代表真实游戏**：暗黑2、魔兽世界的字体带描边、阴影，背景是真实游戏画面，识别难度更高。M2 开工前必须用**真实截图**再测一轮。

## 踩坑

- **PowerShell 5.1 脚本不能带非 ASCII 字符**：gen.ps1 最初写了中文注释，保存为无 BOM 的 UTF-8。在新开的 `powershell -File` 进程里，`Add-Type -AssemblyName System.Drawing` 没有生效，后面所有 `System.Drawing` 类型都报"找不到"。把注释改成纯 ASCII、其他内容一字不改后就正常了，重新生成的两张 PNG 和实测用的原图逐字节一致。结论：给 5.1 用的 `.ps1` 要么保持纯 ASCII，要么存成带 BOM 的 UTF-8。
